## 수량 룰 (data-driven)

| id | regex | 곱수 | 예시 |
|---|---|---|---|
| sku_n_plus_n | `(\d+)\s*\+\s*\1` | n | 1+1 → ×1 (SKU 자체가 1+1 셋트) |
| event_n_count | `할인이벤트[:\s]*(\d+)개` | n | 할인이벤트: 3개 → ×3 |
| n_count_colon | `(\d+)개\s*:` | n | 2개 : → ×2 |

## 핵심 가드 (CRITICAL)

1. **shmaOrdNo 단일 키 매칭** (받는분 이름 매칭 절대 금지)
2. **수량 룰**: SKU N+N 셋트 단위 반영
3. **빈박스 ! 정확매칭**
4. **state 차집합** + cross-validate (사용자 수동 처리 시 state 거짓 가능성)
5. **사이클 시작일 이전 SKIP** / post-cycle SKIP 룰 없음 (사용자 다운 시점 컷오프)
6. **헤더 23 컬럼** + **출고희망일 빈칸**
7. **이더(E*) vs 뉴트리(N*) 분리 업로드**
8. **사용자 fallback**: 010-0000-0000 / 00000 / 주소 사방넷 자동입력
9. **사용자 confirm 게이트** (--report-only 모드)
10. **자동 stop 조건** 6가지 (auto_stop_thresholds in mapping_rules.json)
11. **fixture 회귀 테스트** 매 사이클 시작 시 자동 통과
12. **충돌 감지** — 동일 우선순위 다중 매칭 시 ABORT
13. **합배송 정렬 (v0.5.0)** — 풀필먼트 엑셀 생성 시 (받는분, 전화번호1) 그룹화. 같은 사람이 multi-row 주문한 경우 인접 행으로 정렬 → 풀필먼트 사이트에서 한눈에 합배송 묶음 확인

## 자동 stop 조건 (mapping_rules.json의 auto_stop_thresholds)

- unmapped_count > 0
- 단일 코드 50%↑ 몰림 (whitelist 제외)
- 우편번호 fallback > 5%
- cross-validate 중복 > 0
- 루미솔 카운트 ≥ 1 (경고)
- 룰 충돌 ≥ 1
