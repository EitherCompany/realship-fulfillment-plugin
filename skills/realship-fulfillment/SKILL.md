# 실배송 풀필먼트 자동 등록 (v2 최종 통합본)

## 개요
## ⚠️ 매핑 운영 원칙 (필독)

스킬 실행 전 반드시 `references/mapping_operation_rules.md`를 읽을 것. 핵심 3원칙:

1. **풀필먼트 신규 상품 등록**: 스마트스토어 원본 상품명 앞 30-40자 최대한 일치
2. **매핑 애매 카테고리**(깔창/브라/영양제/무릎보호대 등): 크로스체킹 엑셀로 사용자 사전 확인 요청
3. **product_mapping.json 추가 규칙**: 배타적 키워드로 카테고리 내 충돌 방지

이 원칙은 플러그인 번들의 일부이며, 실배송 스킬을 사용하는 모든 Claude 세션에서 지켜져야 한다.


실배송 주문을 사방넷 풀필먼트(창고)에 자동 등록하는 end-to-end 스킬.
이전 `real-shipping`(스마트스토어 변환 전용)과 `realship-fulfillment`(사방넷 주문 수집) 두 스킬이 통합된 최종본이다.

두 가지 입력 경로를 지원한다:

| 경로 | 입력 | 주 사용처 |
|------|------|-----------|
| **A. 사방넷 관리자 경로** | 사방넷 관리자 API에서 수집한 주문 JSON | 매일 오후 2시 주문마감 후 자동 처리 |
| **B. 스마트스토어 경로** | 스마트스토어 "전체주문발주발송관리" 엑셀 | 특정 쇼핑몰만 수동 처리, 테스트, 백업 |

두 경로 모두 동일한 매핑 엔진(상품번호+키워드 이중 매칭)과 동일한 23컬럼 출력 포맷을 사용한다.

## 전체 처리 흐름

### 경로 A: 사방넷 관리자에서 자동 수집
```
1. 사방넷 관리자 로그인 (Chrome MCP)
2. 주문 수집 (전날 14:01 ~ 금일 14:00, 001+002 상태)
3. 빈박스 vs 실배송 분류
4. 실배송 주문 → 상품코드 매핑 + 수량 변환
5. 사업자별(E/N) 분리 풀필먼트 발주등록 엑셀 생성
6. 사방넷 풀필먼트 엑셀 업로드
7. 리포트 생성
```

### 경로 B: 스마트스토어 엑셀 업로드
```
1. 사용자가 스마트스토어 주문 엑셀(.xlsx) 업로드
2. 엑셀 파싱 → 상품번호+옵션 추출
3. 상품코드 매핑 + 수량 변환
4. 사업자별(E/N) 분리 풀필먼트 발주등록 엑셀 생성
5. 사방넷 풀필먼트 엑셀 업로드
```

## Step 1: 사방넷 관리자에서 주문 조회 (경로 A 전용)

Chrome MCP에서 사방넷 관리자 로그인 상태로 실행:

```javascript
window.location.hash = '#/order/order-confirm';
```

필요 필드 (`tableData` 또는 주문확인처리 API):
- `ordNo`, `shmaOrdNo`: 주문번호
- `shmaId` / `shmaNm`: 쇼핑몰 (shop0075=쿠팡, shop0055=스마트스토어)
- `clctPrdNm`, `clctSkuNm`: 상품명/옵션
- `ecptRmteTotAddr`, `rmteZipcd`: 주소/우편번호
- `ecptRmteNm`, `ecptRmteTelNo`: 수취인/전화
- `shpmtEtcFldVl`: 배송메시지
- `wyblNo`: 운송장번호 (빈박스 식별용)
- `ordQty`: 수량

조회 조건: 전날 14:01 ~ 금일 14:00, 상태 001(미확인)+002(확인).

## Step 2: 빈박스 vs 실배송 분류 (경로 A 전용)

| 조건 | 분류 |
|------|------|
| 쿠팡(shop0075) + 주소에 `%` 포함 | 빈박스 |
| 스마트스토어(shop0055) + 배송메시지 "문 앞에 놓아주세요!" + 빈박스 송장목록에 존재 | 빈박스 |
| 위 조건에 해당하지 않음 | **실배송** |

분류 로직:

```python
def classify(order, binbox_waybills=set()):
    addr = order.get('ecptRmteTotAddr', '')
    msg = order.get('shpmtEtcFldVl', '')
    mall = order.get('shmaId', '')
    wybl = order.get('wyblNo', '')

    if mall == 'shop0075' and '%' in addr:
        return 'binbox'
    if mall == 'shop0055' and '문 앞에 놓아주세요!' in msg:
        if wybl and wybl in binbox_waybills:
            return 'binbox'
        return 'binbox_candidate'  # 사용자 확인 필요
    return 'realship'
```

`binbox_candidate`는 `binbox-processing` 스킬이 처리한 송장번호 목록과 대조하여 확정한다.
대조할 데이터가 없으면 사용자에게 확인 요청.

## Step 3: 상품코드 매핑 (경로 A/B 공통)

`scripts/product_mapping.json`을 사용한 2단계 매핑:

### 매핑 우선순위
1. **상품번호별_매핑** — 스마트스토어 `상품번호` + 색상 + 사이즈로 정확 매칭
2. **키워드_매핑** — 상품명/옵션에서 키워드 검색 (배열 순서대로 첫 매칭 사용)
3. 둘 다 실패 → `unmapped` 리포트

### 키워드_매핑 규칙 유형
```
- 단일 code 매핑 (뉴트리정 영양제 16종)
- 사이즈_매핑 (아치 기능성 깔창 6사이즈)
- 색상_사이즈_매핑 (구름쿠션 깔창 - 검은색/회색 × 6사이즈)
- 옵션_분기 (양말 20p - 색상 혼합 구성)
```

### 색상 정규화
스마트스토어 옵션 "블랙"/"그레이" → 매핑 키 "검은색"/"회색" 자동 변환
(상품번호별_매핑은 raw 색상 키, 키워드_매핑 구름쿠션은 정규화 색상 키 사용)

### 세트 수량 변환
옵션 문자열에서 추출:
- `1+1` → ×1
- `2+2` → ×2
- `3+3` → ×3
- `N개` → ×N

## Step 4: 풀필먼트 발주등록 엑셀 생성

스크립트 실행:

```bash
python3 <skill-path>/scripts/create_fulfillment_excel.py \
  --orders <사방넷_JSON_또는_스마트스토어_XLSX> \
  --mapping <skill-path>/scripts/product_mapping.json \
  --output fulfillment_YYYYMMDD.xlsx
```

출력 (기본: 사업자별 분리):
- `fulfillment_YYYYMMDD_ether.xlsx` (E코드 = 이더컴퍼니 공산품)
- `fulfillment_YYYYMMDD_nutri.xlsx` (N코드 = 뉴트리정 영양제)
- `fulfillment_YYYYMMDD_unmapped.xlsx` (매핑 실패 — 수동 확인 필요)

`--no-split` 플래그로 분리 없이 단일 파일 출력 가능.

## 매핑 실패 대응

매핑 실패 상품이 발견되면:
1. `product_mapping.json`의 `키워드_매핑` 배열에 새 규칙 추가
2. 뉴트리정 영양제 → 단일 `code` 매핑
3. 이더컴퍼니 깔창/의류 → `사이즈_매핑` 또는 `색상_사이즈_매핑`
4. 양말처럼 혼합 구성 → `옵션_분기` 사용
5. 사방넷 풀필먼트 재고조회 UI에서 상품코드 확인 후 `코드별_상품명` 추가

### 키워드 규칙 예시
```json
{
  "name": "뉴트리정_신규상품",
  "keywords_all": ["뉴트리정", "신규키워드"],
  "code": "N00200099"
}
```

## 에러 처리

| 상황 | 대응 |
|------|------|
| 새 상품 매핑 실패 | product_mapping.json에 키워드 규칙 추가 |
| 풀필먼트 로그인 실패 | 사용자에게 수동 로그인 요청 |
| 엑셀 업로드 실패 | 엑셀 파일을 사용자에게 제공, 수동 업로드 요청 |
| 빈박스 분류 불확실 | `binbox_candidate`로 표시, 사용자 확인 요청 |
| 풀필먼트 MCP 응답 제한 | XLSX 파일 다운로드 후 수동 업로드로 폴백 |

## 타 스킬과의 연동

- **binbox-processing**: 빈박스 처리된 송장번호 목록을 받아 분류에 활용
- **waybill-processing**: 풀필먼트에서 송장이 나오면 사방넷 관리자에 송장입력·송신

## ⏱️ 1차 vs 2차 차이 (중요)

**차수별 선행 스킬에 따른 주문 상태가 완전히 다름**:

| 차수 | 선행 스킬 | 주문 상태 | 일괄확정 필요성 |
|------|----------|----------|-----------------|
| **1차** (아침 14시 마감) | binbox-processing 먼저 실행됨 | 대부분 이미 **002 확정** 상태 | **선택적** — 시간 부족하면 스킵 OK |
| **2차** (오후 추가분) | binbox 스킬 미실행 | 신규 **001 미확정** 다수 | **필수** — 안 하면 엑셀에서 누락 |

### 1차 처리 시 시간 절약
빈박스 스킬이 1차 일괄주문확정(001→002)을 이미 수행함. 실배송 스킬 시작 시:
- 주문서확정관리 빠르게 조회해서 자료수 >0이면 확정 실행
- **"시간이 생명"**일 경우 주문서확정관리 스텝 건너뛰고 바로 엑셀 다운로드로 이동 가능 (대부분 002 상태)

### 2차 처리 시 반드시
빈박스 스킬 없이 2차만 단독 실행되는 경우가 많음. **일괄주문확정 스킵하면 신규 001 주문 누락**.

## 🚧 2차 처리 (오후 수집분) 완전 자동화 플로우

1차 처리 이후 들어온 추가 주문 처리 시:

### Step 1: 주문 재수집 트리거 (필수)
```
사방넷 주문서수집(자동) 페이지
 → 체크박스 전체 선택
 → [주문수집(신규+주문확인)] 클릭
 → 결과 분기:
    (A) "N분 뒤 재시도" 알림 → 이미 수집 중 → **반드시 N분 대기 후 Step 2로**
    (B) 즉시 수집 시작 → 수집 완료 대기 (보통 10~30초)
```
❗ **중요**: Step 1을 스킵하거나 "수집 중" 알림을 무시하면 신규 001 주문이 빠진 채로 Step 2로 넘어가게 됨 → 누락 발생.

### Step 2: 일괄주문확정 (001 → 002) — Step 1 완료 후 반드시 실행
```
사방넷 주문서확정관리 페이지
 → 오늘 수집일자 필터 + 주문미확정 체크
 → [검색]
 → 자료수 확인:
    (A) 0건 → Step 1이 아직 반영 안 됐을 수 있음 → 30초~1분 후 재조회
           여전히 0건이면 실제로 미확정 주문이 없는 것 → Step 3 진행
    (B) N건 (N ≥ 1) → 체크박스 전체 선택 → [일괄주문확정] 클릭 → 건별 "(성공)" 응답
```
❗ **흔한 실수**: 주문수집 트리거 **직후** 바로 확정관리를 열면 아직 001이 반영 안 돼 0건으로 보임.
이때 "할 것 없다"고 판단하면 신규 주문 누락. 반드시 Step 1 완료 후 **30초~1분 대기** 필요.

### Step 3: 주문서확인처리 엑셀 다운로드 (UI 자동화 필수)
**⚠️ 중요**: API 응답에는 주소(ecptRmteTotAddr) 필드가 **없음**. 빈박스 분류(쿠팡 주소 `%` 체크)를 위해 **반드시 UI에서 엑셀 다운로드**.

```
주문서확인처리 페이지
 → 배송희망일 또는 수집일 오늘로 설정
 → [검색] → [다운로드] 버튼 클릭
 → Excel 생성 → Downloads 저장
```

### Step 4: 1차 기처리 제외 (차집합)
1차에서 풀필먼트에 올린 주문의 `shmaOrdNo`를 `sabang_orders.json`에서 로드해 2차 엑셀에서 차집합.

### Step 5: 2차 분류 (빈박스 비율 높음 — 정상)
**2차에서는 빈박스 주문이 1차보다 훨씬 많이 발생** (1차 마감 후 추가 유입되는 체험단 주문 때문).
예: 2차 441건 중 빈박스 352건, 실배송 9건. 이는 정상 패턴.
- 쿠팡 + 주소에 `%` → 빈박스
- 스마트스토어 + "문 앞에 놓아주세요!" → 빈박스 후보
- 나머지 → 실배송

### Step 6: 매핑 + 업로드
1차와 동일한 매핑 엔진. **업로드 전 수량 경고 체크 필수**.

## 🔥 2026-04-27 추가 학습 (필독)

### 1. 주문수집 default 3일 함정 — **반드시 5일로 변경**
사방넷 주문서수집(자동) 페이지의 **수집기간 input은 default가 3일** (예: 0425~0427).
JavaScript로 수집 기간을 변경할 때:
```javascript
// 시작일 → 4일 전, 종료일 → 오늘
function setInput(el, value) { 
  const setter = Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value').set;
  setter.call(el, value);
  el.dispatchEvent(new Event('input', {bubbles: true}));
  el.dispatchEvent(new Event('change', {bubbles: true}));
  el.dispatchEvent(new Event('blur', {bubbles: true}));
}
const inputs = Array.from(document.querySelectorAll('input')).filter(i => i.offsetParent && /^2026\d{4}$/.test(i.value));
setInput(inputs[0], '20260423'); // 시작
setInput(inputs[1], '20260427'); // 종료
```

### 합포장 검증 의무화

### "할인이벤트: N개" 마케팅 옵션 패턴
- 옵션이 `할인이벤트: N개 : XX 추가할인` 같은 비표준 텍스트인 경우 옵션관리코드/판매자상품코드 모두 비어있을 가능성 큼
- create_fulfillment_excel.py의 `get_set_multiplier`가 이미 `(\d+)\s*개` 정규식으로 N을 추출하지만, 매칭은 키워드 매핑(상품명+옵션)으로 진행해야 함
- 키워드 매핑이 옵션 안 텍스트만 보지 않고 **상품번호+상품명으로 1차 매칭** 후 옵션의 N개로 수량 결정

### 매핑 실패 → SKU 마스터 자동 검색

  2. 추정 SKU 코드를 사용자에게 보여주고 승인 요청
  3. 승인 시 product_mapping.json 키워드_매핑에 자동 추가
